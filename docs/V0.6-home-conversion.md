## Sign-up → onboarding → dashboard

- `/register?next=…`: a signed-in ambassador is redirected straight to `next`; a new one goes to `/dashboard/welcome?next=…` and the finish button continues there (same-site paths only).
- Welcome = "Welcome to Studio. Goal: your first recommendation." with a 5-item checklist and `x / 5` progress (`src/lib/sales/onboarding-checklist.ts`) over the existing 6 onboarding steps; finish: "You're ready to start."
- Dashboard: one **next action** card first (`src/lib/sales/primary-action.ts`, tested): checklist → first prospect → first message → follow-up → demo → hand-over for the proposal → follow-up on the proposal → next opportunity.

## Analytics (first-party, no new dependency)

- `funnel_events` table + `admin_activation_funnel()` — migration `20261010000001_funnel_events.sql` (**not pushed to prod yet**), SQL test `supabase/tests/funnel_events_test.sql`.
- Public events carry **no identifier and no cookie** (aggregate counts, no consent needed); ambassador events carry the affiliate id from the server session only. Browser events go through `/api/events` (`src/lib/analytics/client.ts`, allow-list in `events.ts`); `signup_*`, `onboarding_*`, `prospect_added`, `prospect_submitted` are recorded server-side where they happen.
- Admin → Sales analytics → **Activation funnel**: % sign-up → link copied / first prospect / first hand-over, opportunities → sales, median time to first action / first prospect, paid revenue per active ambassador, raw event counts. Shows an empty funnel (no crash) until the migration is applied.
