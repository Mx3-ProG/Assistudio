# V0.5 — Guided pipeline ("next best action")

Studio must keep answering one question: **what is the next best action this
ambassador should take with this prospect?** Not "here are all your tools" but
"tell me where you are and I tell you what to do now".

## 1. Audit (before implementation)

| Question | Finding | Decision |
| --- | --- | --- |
| Pipeline? | One CRM: `prospects` (board + list), `prospect_stage` enum: new, contacted, replied, qualified, (interested, hidden since V0.3), appointment, proposal, checkout, won, lost | Keep it as the single pipeline. Re-offer `interested`, add `proof_sent`, `handed_off` |
| Next action? | `src/lib/sales/next-action.ts` (one rule per stage, hardcoded wording) + V0.4 follow-up sequences | Replaced on the board/home by the content-driven guide; timing reuses the V0.4 sequences |
| History? | None per prospect (only `stage_changed_at`) | New append-only `prospect_events` |
| Sector resources? | V0.4 `markets` (+ keywords, offer) and `sales_content` (pitch, case studies, messages, objections, questions, sequences) | Reused as is by the guide |
| Hand over to Studio? | No action. Existing building blocks: Support thread (whole staff team), client dossiers (attributed quote → checkout) | "Hand over to Studio" = structured Support message + stage + event; quote → existing dossier |
| Source of truth? | Pricing copy, product knowledge, offers table, settings | New `fact` content + live figures from `offers` / `settings` |
| Automations? | Follow-up sequences, email outbox, daily cron | Nothing is ever sent automatically to a prospect |

## 2. What was built

**Content (admin-editable, Admin → Sales content, per locale, versioned)** — four new kinds:
- `stage_guide` — per stage: goal, why, what to do, what to say (message stage), what to show (project / page / offer), questions, information to collect, what to avoid, outcomes ("I sent the message" → next stage), when to escalate. A row with `targetKey` = sector override (seeded example: hotels, first contact).
- `reply` — what the prospect said → **level 1** answer yourself / **level 2** recommended answer / **level 3** hand over to Studio, meaning, words to use, next question, proof, next stage. Seeded: interested, price, send info, already a website, someone handles it, no time, call me later, talk to someone, technical/legal question, not interested.
- `fact` — official information with a level, incl. **what you can promise / never promise**.
- `find_source` — where to find the first 3 prospects (network, contacts, professional relations, places you're a client of, local, LinkedIn, Instagram).

**Engine** (`src/lib/sales/guide.ts`, pure, tested): picks the guide (sector override → generic), decides act now / follow up now (sequence step due, "no reply for N days") / wait until a date (or the date the ambassador planned), filters replies by stage, computes progress (`reachedCounts`) and the first-sale path. Pending commissions never count as earned.

**Screens**
- Home: before the first paid sale, "Let's make your first sale" — *Do you have someone in mind? Yes / Not yet*. Yes = 4 questions (who, sector, relation, where you are) → the prospect's guided page. Not yet = where to find 3 people. Then *Your next actions*, *Your first sale* checklist (9 steps), *Your progress* (small wins). The money figures are folded under *My numbers* until the first sale.
- `/dashboard/prospects/[id]` — **Your next action**: why · what to do · what to say (sector + relation-aware message, copy / WhatsApp / email) · what to show (sector projects, page, offers) · questions · what to collect · avoid · *And then?* outcome buttons. Below: *They said…* reply picker with levels, **Hand over to Studio**, history.
- `/dashboard/prospects/start` — the same "Yes / Not yet" start, used by the copilot intents and the sector sheets.
- `/dashboard/sales-center/facts` — live official figures (prices, your rate, sponsor rate, validation period, minimum payout), can / never promise, searchable official answers with levels.
- Board: cards open the guided page and show the next action; `?edit=id` opens the edit dialog.

**Hand over to Studio** keeps everything: the prospect stays in the ambassador's CRM (attribution, commission and history untouched); Studio receives a structured message in the ambassador's Support thread (reason, note, stage, sector, ambassador code; contact details only with the prospect's agreement); the outcome buttons can never skip this form (client + server guard). A quote goes through the existing client dossier, which is attributed to the ambassador.

## 5. Not done / recommendations
- **Internal social proof** (§12): not built — the only real sources today are the opt-in leaderboard and the live sales feed. A "sales this month in the network" figure needs a SQL aggregate + Studio's agreement on what to show. Nothing was fabricated.
- **Staff view of handed-over prospects**: today via the Support inbox. A dedicated "Opportunities handed over" admin list (read of `prospect_events` type `handed_off`, staff RLS already allows it) would help Studio's follow-up.
- The legacy `nextBestAction()` (`next-action.ts`) is no longer shown on the board; it can be removed once the guided page has run in production.
- Admin editing of guides is the generic JSON editor; a form editor per kind would make Studio's daily edits easier.
- Translations DE/ES/… of the guidance content.
