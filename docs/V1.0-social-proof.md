# V1.0 — Social proof (testimonials, case studies, verified proofs)

Goal: a prospect sees what Studio builds and can test it; a partner sees how a
recommendation becomes a payment; existing users enrich the proof through
**Give my review**. Absolute rule: nothing is invented. Anything illustrative
carries a visible **Simulation** / **Exemple de fonctionnement** badge.

## Data (migration `20261013000001_social_proof.sql`, NOT pushed yet)

| Table | Role |
| --- | --- |
| `testimonials` | One review: type `client` / `ambassador`, rating, content, recommendation, `media_type` `text` / `video`, video/poster/photo/logo storage paths, consent (date, version, text), `status` `pending` / `approved` / `rejected` / `hidden`, `verified` + basis, presentation metadata (placements, service, name display, featured, order, linked case study). |
| `testimonial_consents` | Append-only log: granted / withdrawn, version, text. |
| `testimonial_invites` | Single-use client links (only the sha256 of the token is stored; 30 days). |
| `social_proof_events` | Real events shown publicly: `commission_paid` (paid payout), `new_client` (paid sale), `testimonial_published`. `proof_type` `real` / `demo` — a demo row can never be published (check constraint). |
| Storage `testimonial-media` | Private bucket, 50 MB, mp4 / webm / mov / jpeg / png / webp. |

Case studies reuse the existing `sales_content` kind `case_study` (Admin → Sales
content) instead of a parallel table. New optional body fields: `result`,
`resultSource`, `demoSlug`, `publicConsentAt` (YYYY-MM-DD), `publicConsentBy`. A
client project is public **only** with a documented public consent
(`src/lib/proof-cases.ts`). Interactive demos (`src/lib/demos.ts`) are always
labelled as demonstrations.

## Rules enforced in SQL (mirrored in `src/lib/proof.ts`, tested)

- No consent → no testimonial. Withdrawal hides at once, empties placements,
  unpublishes linked events, and the review can never be approved again.
- `verified` is computed at submission: approved partner account, or customer
  with a paid sale. A trigger forbids changing it — and the words, rating,
  author and consent — afterwards. Staff edit presentation only; the name
  display can only become *more* private than the author chose.
- Media must sit in the author's folder (`a/{profile}` / `c/{invite}`) and exist
  in Storage; they can be removed, never swapped.
- Rejecting needs a reason; one pending review per partner; 3 per 30 days.
- Proof events copy value + date from the source row (never typed), are
  unpublished by default, and stop showing if the source becomes invalid
  (refund, failed payout, withdrawn review). Public dates are month precision.
- Public reads go through `public_testimonials()`, `public_testimonial_media()`,
  `public_proof_events()`: whitelisted columns, no email / ids of people / paths.
- Every staff action is audited (`audit_logs`).

## Routes & API

- Partner: `/dashboard/review` (form + my reviews + withdraw), nav entry "Donner
  mon avis", milestone prompt on the dashboard (first sale / commission / payout).
- Client: `/{locale}/review/{token}` (noindex, robots-disallowed).
- Admin: `/admin/proof` — To review / Published / Rejected-hidden / Client invites / Proof events.
- `GET /api/proof/testimonials?placement=&type=&limit=`, `GET /api/proof/events`
  (public, `no-store`), `GET /api/proof-media/{id}/{video|poster|photo|logo}`
  (status re-checked every request → 302 to a 5-minute signed URL; staff and the
  author may preview before moderation), `/api/demo-proof-media` (demo only).
- Writes: server actions in `src/app/actions/proof.ts`.

## Where proof is displayed

| Placement | Page |
| --- | --- |
| `client` | `/studio` and private sales pages `/p/{slug}` — section "Des entreprises accompagnées…" (work band, case studies, testimonials, verified activity) |
| `home` | Partner home — money flow + payout proofs + testimonials |
| `ambassador` | `/partners` — same partner section |
| `offers` | `/pricing` (below the plans) |
| `sales_center` | Dashboard → Sales Center (proof a partner can show) |
| `app` | Dashboard overview |
| `case_study` | stored (`case_study_key`), for a case-study page later |

Every block renders nothing without real content, except the partner money
flow, which is a labelled simulation computed from the real offer and settings
until staff publish real payout proofs.

## Performance & motion

Video files are requested only on play (poster first, `preload="metadata"`,
one video at a time); posters, photos and logos are resized in the browser
(max 960 px, WebP) before upload. The work band scrolls slowly on desktop
pointers (paused on hover/focus) and is a native swipe row on phones;
reveal-on-scroll uses CSS scroll-driven animations; everything is static under
`prefers-reduced-motion`. No counters (no real aggregated figures yet).

## Verification (2026-10-05)

`npm test` (174), `npm run db:test:local` (16 suites, 39 social-proof
assertions), typecheck, lint. Headless Chrome on an isolated demo copy: 4 pages
× desktop / tablet / mobile without horizontal overflow or console errors; RTL
(ar) and dark theme; full flow: consent required → partner review with vertical
video + photo → pending media 404 for visitors → reject without reason refused
→ approve → placements → shown on home, video loaded only on play → client
invite → single use → payout proof created + published → video deletion (404,
falls back to text) → consent withdrawal (gone from API and media).
